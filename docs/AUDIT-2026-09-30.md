# Аудит kinopap — 30 сентября 2026

## Итог аудита

В ходе аудита код и конфигурация не изменялись, файлы не добавлялись. Этот отчёт сохранён отдельным файлом по последующему запросу пользователя. Production, SSH и рабочая БД не затрагивались.

Проверены API, авторизация, БД, импорт контента, web/mobile, плееры и тестовая инфраструктура. Основа проекта хорошая: общие типизированные контракты, разделение приложений и пакетов, миграции, немало тестов. Главные проблемы — **потеря данных при дедупликации, неправильный выбор серий, безопасность и восстановление после сбоев**.

Гарантировать нахождение буквально **всех** багов нельзя. Ниже разделены воспроизведённые ошибки, выводы по коду и условные риски. Ссылки и номера строк соответствуют состоянию проекта на момент аудита.

## 1. Воспроизведённые баги

### Высокий приоритет — исправлять первыми

### 1. Обход SSRF-защиты через IPv4-mapped IPv6

Проверка блокирует `127.0.0.1`, но пропускает `http://[::ffff:127.0.0.1]/` и `http://[::ffff:10.0.0.1]/`. URL нормализует адрес в шестнадцатеричную форму, которую регулярное выражение не распознаёт. Это позволяет URL-источнику обратиться к внутренней сети из процесса загрузки.

Воспроизведение проверяло сам guard, без реальных сетевых запросов к внутренним адресам.

**Рекомендация:** нормализовать IP перед проверкой, проверять оба семейства адресов; закреплять проверенный адрес за соединением, закрывая также окно DNS rebinding.

Источник: [url-source.ts:83–130](../packages/ingest/src/connectors/url-source.ts#L83-L130).

### 2. Заблокированный администратор сохраняет административные права

После `users.isActive = false` ранее выданный access-токен продолжает работать: `/auth/me` вернул **200**, создание инвайта — **201**. Middleware проверяет подпись JWT, но не актуальную активность пользователя; роль тоже берётся из старого токена. Окно — до истечения access-токена, обычно 15 минут.

**Рекомендация:** проверять актуальное состояние учётной записи для защищённых операций, особенно административных; предусмотреть отзыв сессий или версию авторизации.

Источник: [auth.ts:29–82](../apps/api/src/plugins/auth.ts#L29-L82).

### 3. Дедупликация каталога удаляет пользовательские данные и медиа

В локальной БД воспроизведены:

- исчезновение избранного — оно вообще не переносится;
- потеря медиа эпизода, когда у объединяемых сериалов совпадают номера сезона и серии.

Причина второго: `media.itemId` переносится, но `episodeId` остаётся связанным с удаляемым эпизодом. Каскад затем удаляет медиа и связанные данные. Кроме того, по коду голоса переносятся **без пересчёта счётчиков и рейтинга**.

Особенно важно: объединение автоматически выполняется при наполнении каталога по умолчанию.

**Рекомендация:** сначала режим предварительного просмотра; затем полный перенос связей через соответствие старых и новых эпизодов, перенос избранного и пересчёт агрегатов.

Источники: [dedupe.ts:164–240](../packages/db/src/repos/dedupe.ts#L164-L240), [catalog-fill.ts:450–454](../packages/ingest/src/catalog-fill.ts#L450-L454).

### 4. Неудачный запуск ingest блокирует повторную загрузку

При недоступной очереди первый запрос возвращает **503**, повторный — **409**. В БД остаётся задача `queued`, хотя в очереди её нет. Автоматическое восстановление обрабатывает только `running`.

**Рекомендация:** согласовать БД и очередь через transactional outbox и стабильный `jobId`; сверять наличие задач в очереди, а не просто завершать все старые `queued` по возрасту.

Источники: [ingest.ts:61–84](../apps/api/src/routes/ingest.ts#L61-L84), [reconcileStaleIngestJobs](../packages/db/src/repos/ingest.ts#L90-L118).

### 5. Импорт путает TMDb ID фильма и сериала

У TMDb movie/tv — разные пространства идентификаторов, но внутренние карты используют только число `tmdbId`.

Воспроизведено:

- отдельными батчами: сериал пропускается как уже существующий фильм;
- одним батчем: создаются две карточки, но **оба медиа привязываются к сериалу**, фильм остаётся без медиа.

**Рекомендация:** использовать составной идентификатор источника — например, `tmdb:movie:id` / `tmdb:tv:id` — во всех запросах, картах и ограничениях.

Источник: [discovery.ts:69–189](../packages/db/src/repos/discovery.ts#L69-L189).

### 6. Резолвер может воспроизводить не ту серию

На подставных источниках подтверждены два случая:

- запрос первой серии сезонного торрента выбирает вторую, если её файл крупнее;
- запрос отсутствующей третьей серии аниме возвращает первую.

В торренте выбирается крупнейший видеофайл, а в аниме отсутствующий эпизод заменяется первым.

**Рекомендация:** выбирать файл по сезону/эпизоду; при отсутствии точного соответствия возвращать «серия недоступна», а не подменять контент.

Источники: [выбор аниме-эпизода](../packages/ingest/src/stream-resolver.ts#L272-L280), [выбор торрент-файла](../packages/ingest/src/stream-resolver.ts#L600-L637).

### Средний приоритет

### 7. Пагинация по году теряет карточки без года

С фикстурой `2020, NULL, NULL` первая страница сообщает, что продолжение есть, а следующая возвращает пустой результат. `NULLS LAST` в сортировке не согласован с условием курсора: сравнение кортежей с `NULL` не даёт нужного результата.

**Рекомендация:** отдельно обработать переход к NULL-значениям и пагинацию внутри них, для обоих направлений сортировки.

Источник: [catalog.ts:270–287](../packages/db/src/repos/catalog.ts#L270-L287).

### 8. Таймаут API неправильно распознаётся и вызывает лишний запрос

Настоящий `AbortSignal.timeout()` возвращает `TimeoutError`, а клиент распознаёт только `AbortError`. Проверка показала **два вызова вместо одного** и сырую `DOMException` вместо `ApiTimeoutError`.

Также по коду: если в runtime нет `AbortSignal.timeout`, дедлайн вообще не создаётся.

**Рекомендация:** различать отмену и дедлайн по сигналам, добавить ручной fallback; не повторять запрос после истечения дедлайна.

Источник: [client.ts:177–273](../packages/api-client/src/client.ts#L177-L273).

### 9. Невалидные фильтры каталога возвращают 500 вместо 400

`/v1/items?type=garbage` и `?limit=oops` дают `internal`. Zod-ошибка из `parseCatalogQuery()` не преобразуется в штатную ошибку валидации.

**Рекомендация:** единая обработка ошибок входных схем.

Источник: [catalog.ts:148–150](../apps/api/src/routes/catalog.ts#L148-L150).

### 10. Поиск авторизованного клиента не передаёт access-токен

После `setToken()` вызов `searchItems()` всё равно отправляет пустые заголовки. Поэтому сервер видит гостя, и предусмотренный поиск нового контента во внешних источниках не запускается. Web SSR-поиск также не передаёт авторизацию.

**Рекомендация:** поддержать опциональную авторизацию поиска и явно определить, где запускается discovery.

Источники: [API-клиент](../packages/api-client/src/client.ts#L345-L350), [серверный discovery](../apps/api/src/routes/catalog.ts#L179-L185), [web-поиск](../apps/web/lib/api.ts#L140-L155).

## 2. Дополнительные проблемы, установленные по коду

Эти сценарии не проверялись на реальном устройстве или многопользовательском PostgreSQL.

| Проблема | Последствие и улучшение |
|---|---|
| **Любой сбой refresh считается смертью сессии** | Сеть, timeout и 500 вызывают очистку токенов. На mobile пользователь при этом остаётся в React-контексте «вошедшим». Разделить временную недоступность и окончательный отказ, синхронизировать контекст. [refresh.ts](../packages/api-client/src/refresh.ts#L58-L84), [mobile API](../apps/mobile/lib/api.ts#L34-L41). |
| **Параллельный refresh отзывает сессии всех устройств** | Две вкладки с одной cookie могут привести к `revokeAllUserTokens`. Восстановление web-сессии обходит общий single-flight. Нужны ротация в рамках семейства сессии, атомарность и политика обработки легитимных гонок. [сервер](../apps/api/src/routes/auth.ts#L185-L210), [web](../apps/web/lib/auth.tsx#L68-L91). |
| **Новые серии уже импортированного аниме не добавляются** | Известный релиз целиком пропускается, `updated` не увеличивается. Частичный импорт тоже может остаться незавершённым. Обновлять ongoing-релизы инкрементально. [anilibria-import.ts](../packages/ingest/src/anilibria-import.ts#L102-L143). |
| **Частичная загрузка сезонов TMDb не восстанавливается** | Карточка запускает гидрацию только при отсутствии всех сезонов. После частичного успеха повторного ремонта нет; новые серии ongoing-сериалов этим механизмом тоже не подтягиваются. [условие запуска](../apps/api/src/routes/catalog.ts#L292-L299), [гидрация](../apps/api/src/lib/tmdb.ts#L237-L287). |
| **Повторный ingest перезаписывает действующие файлы неатомарно** | Копирование идёт поверх доступного зрителям каталога до публикации в БД. Сбой может оставить смесь старых и новых сегментов. Использовать версионированные каталоги и атомарное переключение. [pipeline.ts](../packages/ingest/src/pipeline.ts#L202-L222). |
| **После фонового прогрева исправляется `warm`, но не ссылки на файлы** | Выданные с `index=1` ссылки сохраняются в кэше, хотя правильный индекс уже известен. Перестраивать согласованную запись кэша целиком. [stream-resolver.ts](../packages/ingest/src/stream-resolver.ts#L485-L490), [catalog.ts](../apps/api/src/routes/catalog.ts#L451-L457). |
| **Web-плеер слишком рано разрешает autoplay** | `resumeSettled` выставляется до ответа `getProgress()`: фильм может начать играть с нуля, затем прыгнуть на сохранённую позицию. Снимать блокировку только после применения прогресса или ошибки. [player.tsx](../apps/web/components/player/player.tsx#L385-L413). |
| **У mobile-плеера нет нормализации относительных медиа-URL** | `/gst/...` передаётся непосредственно в нативный источник. Кроме того, выбирается первый HLS без перебора альтернатив и HTTP fallback. Нужен общий выбор источника с абсолютными URL. [mobile player](../apps/mobile/app/watch/%5BitemId%5D/%5BmediaId%5D.tsx#L226-L240). |
| **Асинхронные ответы могут обновить уже другой экран** | Web watch не отбрасывает старые ответы; mobile search не имеет защиты от смены запроса и не обрабатывает rejection; мутации/пагинация комментариев не привязаны к поколению текущего item. Ввести отмену или идентификатор запроса. [watch](../apps/web/app/watch/%5BitemId%5D/%5BmediaId%5D/watch-client.tsx#L57-L70), [search](../apps/mobile/app/search.tsx#L38-L53), [comments](../packages/shared/src/use-comments.ts#L102-L162). |

| **Гонки голосования и оптимистичных откатов** | `setVote()` читает прошлый голос без блокировки: параллельные запросы могут конфликтовать или дважды изменить счётчики. | **Ограничение локального источника обходится симлинком** | Проверяется строковый путь, но не фактический `realpath`. Симлинк внутри разрешённой папки может вести наружу. [local-folder.ts](../packages/ingest/src/connectors/local-folder.ts#L28-L36). |

Ещё несколько менее срочных дефектов:

- заявленный запрет апскейла нарушается, если ни одно запрошенное качество не помещается — [ladder.ts](../packages/ingest/src/media/ladder.ts#L27-L35);

## 3. Безопасность и эксплуатация: условные риски

### Просмотр фактически открыт гостям

Анонимный запрос `media-links` вернул **200** и файл. Маршрут также может создавать запись media и запускать внешний резолв. Если kinopap должен быть закрытым клубом по инвайтам, это существенное нарушение модели доступа. Если гостевой просмотр задуман — это не баг, но нужны отдельные ограничения стоимости таких запросов.

Источник: [маршрут](../apps/api/src/routes/catalog.ts#L324-L360).

### Доверие proxy зависит от реальной сети

PM2 включает `TRUST_PROXY=true`. При доступности API напрямую это позволяет подделывать клиентский IP и обходить IP-лимиты. Текущий firewall не проверялся.

Источник: [конфигурация](../ecosystem.config.cjs#L60-L63).

### Сбой logout скрывается

Если API не очистил refresh-cookie, web показывает выход, но перезагрузка может восстановить вход. Нужна явная обработка неуспешного серверного выхода.

Источник: [auth.tsx](../apps/web/lib/auth.tsx#L112-L118).

### Dev-разрешение HTTP может остаться в native-конфигурации

Плагин добавляет cleartext/ATS-разрешения при флаге, но не удаляет их при последующем запуске без него. Риск относится к повторному prebuild без очистки.

Источник: [плагин](../apps/mobile/plugins/with-dev-cleartext.js#L23-L53).

### Быстрый старт на чистой машине неполон

Compose требует заранее существующий внешний том `kinopap_pgdata`, но инструкция не создаёт его.

Источники: [Compose](../docker-compose.yml#L65-L71), [README](../README.md#L67-L74).

## 4. Что улучшить системно

1. **Сначала защитить данные:** дедупликация с предварительным просмотром, полный перенос связей, проверки инвариантов и возможность отката.
2. **Сделать задачи восстанавливаемыми:** outbox, идемпотентность, сверка БД/очереди, версионированная публикация медиа.
3. **Унифицировать идентичность контента:** источник + тип + внешний ID; отдельно точная идентичность сезона, эпизода и торрент-файла.
4. **Разделить состояние сессии и состояние сети:** временный сбой не должен уничтожать вход; logout/block должны иметь понятные гарантии.
5. **Усилить наблюдаемость:** отдельная readiness-проверка БД/Redis, метрики зависших задач, времени до первого кадра, ошибок резолва и переключений источников. Сейчас `/healthz` всегда отвечает `ok`. [app.ts](../apps/api/src/app.ts#L153-L154).
6. **Тестировать не только функции, но переходы:** медленная сеть, две вкладки, смена серии во время загрузки, параллельные мутации, восстановление после частичного сбоя.

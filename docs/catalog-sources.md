# Источники каталога: как расширить «Зал» до 15–20к тайтлов

Документ для владельца проекта. Только факты из кода и официальных доков источников;
где цифра не подтверждена — помечено «нужно проверить».

**Короткий вывод.** Рост числа тайтлов дешевле всего даётся не новыми API, а
поднятием уже существующего TMDb-fill (сделано в этом заходе) и обходом
20-на-страницу через **TMDb daily ID exports**. Дальше по отдаче на час работы:
**AniList** (масштаб аниме) и **TVmaze** (сезоны/эпизоды для всего ТВ-половины).
Русская локализация и актёры — это **Shikimori** и **kinopoisk.dev**, но это
обогащение, а не рост числа строк.

## 1. Где каталог стоит сейчас

> **Замер 29.09.2026** (прод, `select count(*) from items`): **24 258 тайтлов** —
> 15 366 фильмов, 7 897 сериалов, 995 аниме; 111 357 строк `media`; 23 215
> тайтлов с `tmdb_id`. Цель этого документа (15–20к, §5.1) **достигнута и
> перекрыта на 21–62%**. Дальше речь идёт о глубине и локализации, а не о числе
> строк: пункты 1 и 5 из §5 сделаны, остальные упираются либо в решение
> владельца, либо в непроверенную предпосылку — разбор в §5.

### 1.1 Чем он наполняется

Единственный bulk-вход — `POST /v1/discover` (`apps/api/src/routes/discovery.ts`),
который ставит в BullMQ джобу `catalog-fill`; сама заливка — `fillCatalog` в
`packages/ingest/src/catalog-fill.ts`. Фазы (`catalog-fill.ts:282–410`):

| Фаза | Что делает | Код |
|---|---|---|
| `years` | TMDb `discover/{movie,tv}` по году выпуска, `sort_by=popularity.desc`, `vote_count.gte` | `catalog-fill.ts:286–304` |
| `genreMatrix` | 7 десятилетий × 16 жанров × 2 типа, «хвост», не попавший в топ года | `catalog-fill.ts:307–327` |
| `lists` | `top_rated` + `trending` + `popular`, 5 страниц × 6 лент | `catalog-fill.ts:330–349` |
| `countries` | `discover` по `with_origin_country` | `catalog-fill.ts:352–368` |
| `collections` | `search/collection` → `collection/{id}`; детали `/movie/{id}` только новым | `catalog-fill.ts:372–410` |
| `anime` | AniLibria (`anilibria-import.ts`): релиз → item + сезон/эпизоды + media | `catalog-fill.ts:444–466` |

Дедуп — по `tmdbId`, затем по `(lower(title), year)` (`packages/db/src/repos/discovery.ts:68–108`).
Пейсинг — очередь на `requestIntervalMs ?? 60` мс, 429 → до 3 попыток со
`sleep(1000·attempt)` (`catalog-fill.ts:138–174`).

### 1.2 Потолок текущих параметров — арифметика

TMDb `discover` отдаёт **20 результатов на страницу**, максимум 500 страниц
(10 000 результатов на один набор фильтров). `bin/fill-catalog.sh` (до этого
захода) и дефолты `buildFillSpec` давали `yearPages=5, genrePages=2,
countryPages=3`, 10 стран, 92 коллекции, `minVotes=30`. Годы по умолчанию —
1950…2026 = **77 значений** (`defaultFillYears`).

| Фаза | Запросов к TMDb | Кандидатов (до дедупа) |
|---|---|---|
| Годы: 77 × 5 × 2 типа | 770 | 15 400 |
| Матрица: 7 × 16 × 2 × 2 | 448 | 8 960 |
| Списки: 5 × 6 | 30 | 600 |
| Страны: 10 × 3 × 2 | 60 | 1 200 |
| Жанровые списки | 2 | — |
| Коллекции: 92 × 2 (+ детали новым) | ~184 | ~600 |
| **Итого** | **~1 494** | **~26 760** |

Это ровно те «~1500 запросов к TMDb», о которых говорит шапка `catalog-fill.ts`.
Кандидатов ~26 760, а в каталоге — **≈5 284** (`8106ccc`). Разница — это не
отсев по `minVotes` (порог уже применён на стороне TMDb в самом запросе), а
**пересечение фаз**: один популярный фильм приходит и из года, и из жанра, и из
страны, и из списка. Дедуп по `tmdbId` и `(title, year)` схлопывает их в 5 284
уникальных строк.

### 1.3 Что поднято в этом заходе

`bin/fill-catalog.sh` теперь по умолчанию бьёт в потолок схемы и умеет
опускаться через env (см. шаг 5). `packages/ingest/src/catalog-fill.ts` получил
`DEFAULT_FILL_PAGES = { yearPages: 10, genrePages: 5, countryPages: 5 }` — дефолт
для прямых вызовов `fillCatalog`; `bin/fill-catalog.sh` задаёт те же числа явно.

| | было | стало |
|---|---|---|
| `yearPages` | 5 | **10** |
| `genrePages` | 2 | **5** |
| `countryPages` | 3 | **5** |
| стран | 10 | **16** (+TR/PL/AR/SE/TH/AU) |
| `animeLimit` | не задан (→1000) | **2000** |
| Запросов к TMDb | ~1 494 | **~3 036** (+детали коллекций) |
| Кандидатов | ~26 760 | **~57 600** → цель 15–20к |

При пейсинге 60 мс это ~3 мин «пола» по времени, с реальным RTT (~150–250 мс) —
порядка 10–15 мин фоновой джобы. Это по-прежнему одна джоба в воркере, не
HTTP-запрос (см. шапку `catalog-fill.ts`).

> Оговорка: дефолты есть в двух местах. `buildFillSpec`
> (`apps/api/src/routes/discovery.ts:72–77`) для запросов, где `yearPages`/
> `genrePages`/`countryPages` **не переданы**, по-прежнему ставит 5/2/3 — это
> `apps/api`, вне текущего скоупа. Скрипт всегда шлёт страницы явно, так что на
> фактический прогон это не влияет; но если дёргать `POST /v1/discover` руками
> без этих полей, глубина будет старой. Выравнивание — отдельное решение владельца.

## 2. Что ограничивает рост сегодня

1. **20 результатов на страницу TMDb discover.** Глубина задаётся только
   `page`, и `yearPages ≤ 10` (`apps/api/src/routes/discovery.ts:37`) даёт максимум
   200 тайтлов на год/тип. Больше — только новыми измерениями запроса
   (жанр × десятилетие × страна), что и делает матрица. Это главный потолок.
2. **`minVotes` режет неочевидное.** `mapEntry` отбрасывает записи без постера и
   с `votes < minVotes` (`catalog-fill.ts:176–181`); по умолчанию 30/20, из скрипта
   `minVotes=30` → TV-порог 18 (`buildFillSpec`, `discovery.ts:83–86`). Ниже порог —
   больше строк, но падает качество выдачи.
3. **Метаданные только по-английски/через TMDb ru-RU.** `TmdbClient.get` жёстко
   ставит `language=ru-RU` (`catalog-fill.ts:157`), но для многих тайтлов перевода
   нет → пустой `plot`, англоязычный `originalTitle`.
4. **Нет актёров и съёмочной группы.** Ни `/credits`, ни `/person` нигде не
   вызываются: таблицы `people` и `item_people` (`packages/db/src/schema/catalog.ts:160–191`)
   под bulk-заливку не заполняются. А это и фильтр «по актёру», и режиссёр в поиске.
5. **Нет трейлеров у старых строк.** `TmdbEnricher.trailer()` (`connectors/tmdb.ts:90`)
   работает только на новом ingest; для уже залитого каталога есть отдельный
   идемпотентный бэкфилл `apps/worker/src/backfill-trailers.ts` (не трогать).
6. **Строка TMDb без сезонов/эпизодов, пока её не откроют.** `hydrateSerialSeasons`
   (`apps/api/src/routes/catalog.ts:262`) дотягивает сезоны лениво при первом
   `GET /items/:id` для `type=serial` без сезонов. До открытия страницы у сериала
   пусто — это бьёт по «новому по подпискам» и по каталогу эпизодов.

## 3. Конкретные источники для расширения

### 3.0 Куда именно это встраивается (seam)

Сейчас **bulk-источники не подключаемы**: `fillCatalog` жёстко знает `TmdbClient`
и AniLibria-фазу, реестра источников нет. Три существующих шва:

- **Поштучное обогащение** — `MetadataEnricher` (`packages/ingest/src/types.ts:87`):
  `find({title, year, type}) → Enrichment[]`. Годится для Shikimori/Kinopoisk/OMDb.
  Ограничение: только поиск по названию (внешнего id в запросе нет), и результат
  уходит в `Enrichment`.
- **Контракт обогащения** — `Enrichment` (`packages/db/src/repos/publish.ts:403`):
  несёт `plot, originalTitle, year, tmdbId, tmdbRating, tmdbVotes, poster*, trailerId/Url,
  genres, countries`. Полей `imdbId/kinopoiskId` и актёров **нет** — их добавление
  требует правки `packages/db` (вне текущего скоупа, решение владельца).
- **Bulk-запись** — `insertCatalogBatch(db, CatalogDraft[], genreMap)`
  (`packages/db/src/repos/discovery.ts:56`). В `CatalogDraft` **обязателен `tmdbId`**
  (`discovery.ts:16`), поэтому источник без tmdbId туда не влезает. Варианты:
  (a) резолвить tmdbId перед вставкой; (b) обобщить `CatalogDraft`/добавить
  repo-функцию (правка `packages/db`); (c) идти путём AniLibria —
  `publishIngest` + `applyEnrichment` с `externalSource`/`externalId`
  (`packages/ingest/src/anilibria-import.ts:47–92`).
- **Новая фаза** встаёт рядом с `anime` в `catalog-fill.ts` (`catalog-fill.ts:443`),
  отчёт — через `FillProgress.phase`.

### 3.1 TMDb daily ID exports — обход потолка discover

- **Что даёт:** полный список валидных TMDb ID (фильмы, сериалы, люди, коллекции)
  с атрибутами `adult`, `video`, `popularity`. Позволяет идти по всему ID-пространству,
  а не по 200 результатам на запрос.
- **API/base URL:** `https://files.tmdb.org/p/exports/movie_ids_MM_DD_YYYY.json.gz`,
  `tv_series_ids_…`, `person_ids_…`, `collection_ids_…`. Формат — JSONL внутри gzip
  (по одному JSON на строку). Файлы живут 3 месяца.
- **Auth:** **не нужен** (официально: «no authentication on these files»). Детали
  тайтла потом тянутся обычным API с ключом.
- **Лицензия:** та же TMDb Terms (см. §4).
- **Покрытие:** всё, что есть в TMDb (миллионы ID).
- **Маппинг:** `items` (+ `tmdbId` уже есть) → `insertCatalogBatch` подходит
  **как есть**. Поля из экспорта (`popularity`) фильтруют ещё до запроса деталей.
- **Цена интеграции:** новый загрузчик экспорта + фильтр по `popularity` + вызов
  `/movie/{id}` или `/tv/{id}` на каждый отобранный ID (1 запрос на тайтл).
  Это **заменяет «20 за запрос» на «1 запрос за тайтл»**: экспорт бесплатно даёт
  кандидатов, платите только за тех, кого решили взять. Пlug в `catalog-fill.ts`
  как новая фаза или отдельный скрипт-бэкфилл (по образцу `backfill-trailers.ts`).

### 3.2 AniList (GraphQL, без ключа)

- **Что даёт:** >500k аниме/манги, связи (`relations`), эпизоды, студии, персонал,
  оценки сообщества, расписание.
- **API:** `https://graphql.anilist.co`. **Ключ не нужен.**
- **Лимит:** **90 запросов/мин**, сейчас API в деградации — **30/мин**
  (docs.anilist.co/guide/rate-limiting). Заголовки `X-RateLimit-*`, 429 с `Retry-After`.
  Повышение лимита сейчас не принимают.
- **Лицензия:** нужно проверить (условия использования AniList; данные сообщества).
- **Покрытие:** аниме — шире и полнее AniLibria (которая даёт ~тысячи релизов).
- **Маппинг:** `items(type=anime)`; `episodes` из `episodes`/`airingSchedule`;
  студии/персонал → `people` + `item_people`; `externalSource="anilist"`,
  `externalId=<id>`. Прямого стрима нет — только метаданные.
- **Цена:** новый GraphQL-коннектор + фаза; из-за обязательного `tmdbId` в
  `CatalogDraft` запись идёт путём `publishIngest`/новой repo-функции. Средняя.

### 3.3 Jikan / MyAnimeList (без ключа)

- **Что даёт:** аниме MAL: эпизоды, расписание выхода, студии, оценки.
- **API:** `https://api.jikan.moe/v4`. **Ключ не нужен.**
- **Лимит:** **60 запросов/мин и 3/сек** (docs.api.jikan.moe; jikan.js).
- **Лицензия:** неофициальный проект (скрейпит MAL) — нужно проверить.
- **Маппинг:** как у AniList.
- **Цена:** как у AniList, но лимит жёстче → строгий пейсинг. Ниже приоритет,
  чем AniList; годится как фолбэк по расписанию.

### 3.4 Shikimori (русские названия/описания)

- **Что даёт:** русские названия и описания аниме, русские оценки — то, чего нет
  у TMDb ru-RU для аниме.
- **API:** `https://shikimori.one/api`. Требуется осмысленный **User-Agent**
  (имя приложения). Ключ для публичных данных не нужен.
- **Лимит:** **нужно проверить** (официальные доки `shikimori.one/api/doc` из моей
  сети недоступны; публичные каталоги говорят про ~5 rps / 90 rpm — не подтверждено).
- **Лицензия:** нужно проверить.
- **Маппинг:** это **enricher**, а не источник новых строк: заполняет `items.title`/
  `plot` у уже существующих аниме. Шов — `MetadataEnricher` (поиск по названию).
- **Цена:** низкая — один `MetadataEnricher`-класс + подключение в pipeline/фазу.
  Даёт максимальный UX-выигрыш на единицу работы для аниме.

### 3.5 TVmaze (без ключа) — сезоны/эпизоды дешевле TMDb

- **Что даёт:** эпизоды на уровне сезона/номера, даты выхода, расписание, каст/crew.
- **API:** `https://api.tvmaze.com`. **Ключ не нужен.**
- **Лимит:** **не менее 20 вызовов / 10 сек на IP**; 429 при превышении; популярные
  эндпоинты кэшируются 60 мин. Не держать >1 idle-соединения.
- **Лицензия:** **CC BY-SA 4.0** — обязательны атрибуция (ссылка на TVmaze) и
  ShareAlike. Есть платный premium/enterprise API с другим лицензированием.
- **Покрытие:** ТВ-шоу; ID **не совпадают** с TMDb → матчинг по названию/году/imdb.
- **Маппинг:** `seasons` (`number`,`title`), `episodes` (`number`,`title`,`airDate`,
  `runtime`,`thumbnailUrl`) — ровно эти колонки есть в `catalog.ts:101–129`.
- **Цена:** коннектор + бэкфилл-скрипт (по образцу `backfill-trailers.ts`) вместо
  ленивого `hydrateSerialSeasons`. Средняя; закрывает пункт 6 из §2 для всей ТВ-половины.

### 3.6 kinopoisk.dev / poiskkino.dev (ключ, платные тарифы)

- **Что даёт:** агрегат Кинопоиск + TMDb + IMDb: русские названия и описания,
  рейтинги КП, актёры/режиссёры, постеры. Заявлено ~1.09M тайтлов.
- **API/base URL:** `https://api.poiskkino.dev` (бывш. kinopoisk.dev).
- **Auth/лимит:** **ключ обязателен**; бесплатно **200 запросов/сутки**; платно
  5 000/сутки (2 500 ₽) или безлимит (5 000 ₽); есть **дамп базы** без лимитов.
- **Лицензия:** нужно проверить (неофициальный агрегатор чужих данных).
- **Маппинг:** `items.kinopoiskId/kinopoiskRating/kinopoiskVotes` **уже есть**
  в схеме (`catalog.ts:50–52`), как и `imdbId/imdbRating/imdbVotes` (`catalog.ts:47–49`);
  актёры → `people`/`item_people`. Но `Enrichment` этих полей не несёт — нужна
  правка `packages/db` (решение владельца).
- **Цена:** enricher + расширение `Enrichment`/`applyEnrichment`. Бесплатный тариф
  (200/сутки) для bulk непригоден — только поштучно или через платный дамп.

### 3.7 OMDb (ключ)

- **Что даёт:** IMDb id и рейтинги (`imdbRating`, `imdbVotes`), рейтинг Rotten Tomatoes.
- **API:** `https://www.omdbapi.com`. **Ключ обязателен.**
- **Лимит:** бесплатно **1 000 запросов/сутки**, платные тарифы до 100k+/сутки.
- **Лицензия:** контент под **CC BY-NC 4.0** — **некоммерческое** использование.
- **Маппинг:** `items.imdbId/imdbRating/imdbVotes` (колонки есть).
- **Цена:** enricher; требует расширения `Enrichment`. Полезна точечно.

### 3.8 Trakt (OAuth/ключ) — сигналы популярности

- **Что даёт:** trending/popular/watched списки, календарь, рекомендации — то,
  **что** стоит заливать, а не метаданные.
- **API:** `https://api.trakt.tv`. Нужен OAuth (или app-ключ для части методов).
- **Лимит:** GET — **500 вызовов / 5 мин** (и authed, и unauthed); POST/PUT/DELETE
  authed — **1/сек**; 429 + `Retry-After`.
- **Лицензия:** нужно проверить.
- **Маппинг:** список названий/годов → резолв в TMDb → обычная заливка. Новых
  строк относительно TMDb почти не даёт.
- **Цена:** новая «list»-фаза, которая резолвит названия через TMDb search. Низкая,
  но и прирост скромный.

### 3.9 Internet Archive (public domain) — легально чистый контент

- **Что даёт:** фильмы и передачи в общественном достоянии — **реально
  проигрываемые** файлы, а не только метаданные.
- **API:** Advanced Search API, `https://archive.org/advancedsearch.php`; метаданные
  item — `https://archive.org/metadata/{id}`.
- **Auth:** ключ не обязателен (с ключом выше квоты). **Лимиты — нужно проверить.**
- **Лицензия:** зависит от item; public-domain-материалы юридически чисты.
- **Маппинг:** `items` + `media` + `mediaFiles`, и это **не** zero-storage: файл
  можно прогнать через существующий ingest (URL-коннектор → ffmpeg → HLS).
- **Цена:** коннектор + ingest-джобы. Единственный источник, дающий легальный
  **плейлист**, а не только карточку. Покрытие — старое/архивное.

### 3.10 Prowlarr / Jackett — **граница проекта**

Prowlarr и Jackett — self-hosted агрегаторы индексеров, отдают единый Torznab-API
поверх множества торрент/Usenet-трекеров. Это ровно то, что README называет вне
скоупа: *«Скрейперы чужих пираток/стримингов в проект не входят»*.

**Явно: подключение Prowlarr/Jackett как источника каталога — решение владельца,
а не дефолт.** Отмечу честно: граница уже частично перейдена — в репозитории есть
`packages/ingest/src/connectors/rutor.ts` (поиск по rutor.info) и
`stream-resolver.ts` (TorrServer + magnet), т.е. zero-storage-плеер по торрентам
уже работает. Если владелец хочет оставить каталог «чистым», а пиратский контур —
только в резолвере стрима (как сейчас), то Prowlarr в **fill** тянуть не нужно:
он ничего не даёт для роста каталога, кроме тех же названий, которые уже есть в TMDb.

### 3.11 Прочее

- **Wikidata:** SPARQL-эндпоинт `https://query.wikidata.org/sparql`, без ключа,
  данные **CC0**. Полезно для связки ID (IMDb/Kinopoisk/TMDb) и фактов о людях;
  покрытие неровное, тяжёлые запросы ограничены таймаутом (нужно проверить точные лимиты).
- **Letterboxd:** официальный API **только по заявке** (`api@letterboxd.com`), OAuth2.
  Открытого доступа нет — как источник не годится.
- **JustWatch:** официального публичного API нет; ходят неофициальные GraphQL —
  ToS и стабильность **нужно проверить**. Данные — доступность на стримингах, не каталог.

### 3.12 Ранжированный шортлист (рост тайтлов на час работы)

1. **TMDb daily ID exports** (+ уже поднятый fill). Остаётся в границах и на
   официальном API, `insertCatalogBatch` подходит без правок (tmdbId есть),
   снимает потолок 20-на-страницу. Ноль новых контрактов, максимум роста.
2. **AniList.** Без ключа, масштаб аниме на порядок выше AniLibria; даёт эпизоды
   и студии. Цена — GraphQL-коннектор и запись через `externalSource` (не через
   `insertCatalogBatch`).
3. **TVmaze.** Не столько «+строк», сколько «+глубина»: закрывает сезоны/эпизоды
   всей ТВ-половины без ключа и дешевле TMDb. Ставлю третьим, потому что это
   лучший прирост качества на час, а не количества.

Русская локализация (Shikimori, kinopoisk.dev) — вне шортлиста: это enrichers,
число строк они не растят.

## 4. Юридические и операционные оговорки

| Источник | Ключ | Бесплатно | Коммерция | Атрибуция | Лимит → пейсинг |
|---|---|---|---|---|---|
| TMDb API | да | да | **нет** (нужен договор) | логотип + дисклеймер | в коде пейсинг 60 мс (~17 rps; TMDb держит ~40) |
| TMDb ID exports | **нет** | да | по TMDb Terms | как TMDb | файлы 3 мес.; детали — по API |
| AniList | нет | да | нужно проверить | нужно проверить | 90/мин (сейчас 30) |
| Jikan | нет | да | нужно проверить | нет | 60/мин, 3/сек |
| Shikimori | нет* | да | нужно проверить | User-Agent обязателен | нужно проверить |
| TVmaze | нет | да | да, при CC BY-SA | **обязательна** + ShareAlike | 20/10 сек на IP |
| kinopoisk.dev | да | 200/сутки | платно | нужно проверить | 200/сутки (free) |
| OMDb | да | 1000/сутки | **нет** (CC BY-NC) | нужно проверить | 1000/сутки |
| Trakt | да (OAuth) | да | нужно проверить | нужно проверить | 500/5 мин GET |
| Internet Archive | нет* | да | зависит от item | зависит от item | нужно проверить |

\* ключ не требуется для публичного чтения.

Ключевое, на что смотреть владельцу:

- **TMDb нельзя использовать коммерчески** без отдельного договора и **нельзя
  кэшировать данные дольше 6 месяцев** (Terms of Use, ред. 20.10.2023). Проект
  «закрытый клуб» — если он остаётся некоммерческим, ок; если появится плата за
  доступ, это уже коммерческое использование → нужен договор с TMDb.
- **OMDb — CC BY-NC**: в коммерческий продукт нельзя.
- **TVmaze — CC BY-SA**: обязательна ссылка на TVmaze, и производные под той же
  лицензией. Простая атрибуция в футере.
- **Rate limits форсируют paced worker.** У нас уже есть механика: очередь
  `TmdbClient.nextAt` + `requestIntervalMs` (`catalog-fill.ts:138–174`) и отдельный
  пейсинг в `anilibria-import.ts:100` (150 мс). Любой новый bulk-источник должен
  идти через такой же интервал и ретраить 429 с `Retry-After`, а не «долбить».
- **Внешние id — истина.** Для аниме уже так (`items_external_uq` на
  `(externalSource, externalId)`, `catalog.ts:89`); новые источники должны
  следовать этому, иначе дубли по названию.
